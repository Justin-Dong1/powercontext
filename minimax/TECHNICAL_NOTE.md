# 一页技术说明

任务：为已有 list_tickets 增加精确 status 筛选，保留默认全量结果、顺序、字段及浅拷贝行为。

模块结构：CLI → seekdb 工程资料索引 → 带来源/摘要的开发上下文 → 官方 MiniMax HTTP → 限定文件修改 → 固定目标/回归测试 → PowerContext Memory → 新 CLI 进程恢复。

导入以 context.json 声明真实规格、代码、测试路径，拒绝目录逃逸，记录每份原文 SHA256。当前实现全文索引评分与词项匹配，按项目隔离。规格更新后重新导入替换该项目资料，版本变化使旧上下文失效。

模型只接收检索得到的资料、任务约束和历史验证状态，输出文件映射；只可改 task.editable_files，样例只允许 tickets.py。目标与回归测试从初始工程开始保持一致；记录修改前断言失败、修改后全部通过，检查受保护来源摘要不变。

PowerContext 使用固定提交的 Memory API，在自己的 SQLite 状态文件中保存项目/任务进展及代码版本。resume 打开新的运行时，读取前序状态，并使上下文 next_action 复用已有验证，避免重复生成代码。

真实调用记录仅保留请求上下文、提供商/模型、响应标识、用量及公开文本/代码；不保存密钥和私有思考。离线夹具 provider=protocol_mock，不能被真实证据重放器接受。

已验证范围：2026-10-30 使用真实 MiniMax-M3 完成修改，真实数据库检索、规格更新、状态跨进程恢复和同一组测试的红绿变化均通过；3项目标测试从断言失败变为通过，3项回归保持通过，真实记录离线重放通过。运行编号为 7c28737a619b494c900f85a8dd63fabe，Python 3.12.14、httpx 0.28.1、PyMySQL 1.2.0，PowerContext 固定提交 fda256c329c6ea9f6e6bb037354922f0f577ac5e。缺口：干净 Linux 环境验证、生态分支发布及平台20分六项验收。尚未宣称正式满分。
